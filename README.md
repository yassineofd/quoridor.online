# Quoridor Online

Static website built from `docs/architecture-spec.md`. Only Python 3.10+ is needed (no Node, no packages).

## Run it

```powershell
python build.py     # generates the site into ./public
python serve.py     # open http://localhost:8000
```

Run `python check.py` to verify status codes, SEO metadata, links, headings, sitemap and robots rules (17 pages).

Run the game tests with `python -m unittest tests.test_engine tests.test_rooms tests.test_http` (fast), plus `tests.test_parity` and
`tests.test_ui` (drive real pages in headless Edge/Chrome; slower).

`python serve.py` also runs the online-play server (`/api/...`, rooms and matchmaking). See [docs/game-engine.md](docs/game-engine.md).

## Hosting anywhere (no domain or address needed)

Every internal link and asset path in the built pages is relative to the page ("../assets/css/styles.css"), so the contents of
`public/` work as they are on any host, any domain, and in any sub-folder (`https://host.example/me/quoridor/`). There is nothing to
configure: run `python build.py` and upload the `public/` folder.

To prove it, serve the site from an arbitrary sub-folder and run the checks there:

```powershell
$env:SERVE_PREFIX="/any/folder"; python serve.py     # open http://localhost:8000/any/folder/
$env:SERVE_PREFIX="/any/folder"; python check.py
```

`site.json` is optional and only matters for things that need a full address:

| Setting | Effect |
|---|---|
| `site_url` (default `""`) | Set to your public address (e.g. `"https://yourname.github.io"`) to add canonical tags, absolute Open Graph URLs and `sitemap.xml`. While empty these are left out rather than guessed. |
| `base_path` (default `""`) | Only for the 404 page, which hosts serve at whatever URL was missing and which therefore can't use relative paths. Set it (e.g. `"/me/quoridor"`) if your host serves the site from a sub-folder; otherwise leave it empty. |

**Vercel:** `vercel.json` (generated by `build.py`) tells Vercel to serve the committed `public/` folder with no build step. After changing
anything, run `python build.py`, then commit **both** `public/` and `vercel.json` and push. Vercel redeploys automatically.

Notes: `public/` includes `_headers` and `_redirects` (Netlify / Cloudflare Pages) and `.nojekyll` (GitHub Pages).

**Static hosts and online play.** Same-device and computer games run entirely in the browser, so they work on any static host
(Vercel included). Private rooms and matchmaking need the Python server in `server/`, which a static host cannot run. The committed
`public/` is therefore built with online play switched off: those pages say "Coming soon" and the forms explain it. To offer online
play, host `serve.py` (it serves the site and `/api/` from one origin), set `"online_server": true` in `site.json` and rebuild, or
for a local try-out `$env:QUORIDOR_ONLINE=1; python build.py`.

## What is built (and what is not)

Built: all pages in the spec, header/footer/mobile menu, design system, SEO files, strict security headers, real 404s, and the
game itself:

| Mode | Status |
|---|---|
| Play with a friend (same device) | Working, in the browser |
| Play against the robot (Easy / Medium / Hard / Expert) | Working, in the browser |
| Private rooms (create / join by link or code) | Working with `serve.py` |
| Online matchmaking | Working with `serve.py` |

Feature flags in `lib.py` (`FEATURES`) control the "Coming soon" badges and which features the pages claim. `local` and `computer` are
always on; `online` and `rooms` follow `online_server` in `site.json`, so a static deployment never advertises a mode it can't run.

## Layout

- `lib.py` config, feature flags, icons, board illustration generator
- `pages.py` all page content
- `build.py` layout, metadata, sitemap, robots, headers
- `serve.py` local server with production-like 404 and room routing, plus the online-play API
- `server/` authoritative rules engine, rooms, matchmaking (Python, standard library only)
- `static/` CSS, JS (game engine, computer opponent, board, game screen, online client), logo, favicon (copied as is)
- `tests/` rules, server, browser play-through and engine-parity tests; `docs/game-engine.md` explains the design

## Before going live

- `og-image.svg` should be exported to a 1200x630 PNG (most social networks ignore SVG previews) and referenced in `build.py`.
- Add PNG icons (180, 192, 512) for iOS and the web manifest.
- Replace the Privacy Policy and Terms drafts with reviewed text; add a real contact channel on `/contact/`.
- Review the "Quoridor" name (and any domain you pick) for trademark issues.
- Set `site_url` in `site.json` once the final address is known, then rebuild.
- Rooms: the host must serve `/room/<id>/` from `room/index.html` with a 200 (see `serve.py`; `_redirects` does this on Netlify / Cloudflare Pages) and route `/api/` to the Python server.
- Online play keeps rooms in memory on one server process, with no persistence. Run a single instance (or add sticky routing) and expect games to end on restart. If it sits behind a proxy, set `QUORIDOR_TRUST_PROXY=1` so rate limits see real client addresses, and put HTTPS in front of it.
- Privacy Policy and Terms drafts now state the facts about what the software stores; have them reviewed and turned into final text.
