# Quoridor Online

Static website built from `docs/architecture-spec.md`. Only Python 3.10+ is needed (no Node, no packages).

## Run it

```powershell
python build.py     # generates the site into ./public
python serve.py     # open http://localhost:8000
```

Run `python check.py` to verify status codes, SEO metadata, links, headings, sitemap and robots rules (17 pages).

## Hosting anywhere (no domain or address needed)

Every internal link and asset path in the built pages is relative to the page ("../assets/css/styles.css"), so the contents of
`public/` work as they are on any host, any domain, and in any sub-folder (`https://host.example/me/quoridor/`). There is nothing to
configure: run `python build.py` and upload the `public/` folder.

To prove it, serve the site from an arbitrary sub-folder and run the checks there:

```powershell
$env:SERVE_PREFIX="/any/folder"; python serve.py     # open http://localhost:8000/any/folder/
$env:SERVE_PREFIX="/any/folder"; python check.py
```

`site.json` is optional and only matters for things that need a full address:

| Setting | Effect |
|---|---|
| `site_url` (default `""`) | Set to your public address (e.g. `"https://yourname.github.io"`) to add canonical tags, absolute Open Graph URLs and `sitemap.xml`. While empty these are left out rather than guessed. |
| `base_path` (default `""`) | Only for the 404 page, which hosts serve at whatever URL was missing and which therefore can't use relative paths. Set it (e.g. `"/me/quoridor"`) if your host serves the site from a sub-folder; otherwise leave it empty. |

**Vercel:** `vercel.json` (generated by `build.py`) tells Vercel to serve the committed `public/` folder with no build step. After changing
anything, run `python build.py`, then commit **both** `public/` and `vercel.json` and push. Vercel redeploys automatically.

Notes: `public/` includes `_headers` and `_redirects` (Netlify / Cloudflare Pages) and `.nojekyll` (GitHub Pages). Static hosts can't serve a
private-room URL like `/room/<id>/` without a server, which doesn't exist yet, so on hosts without that rewrite those links show the 404 page.

## What is built (and what is not)

Built: all pages in the spec, header/footer/mobile menu, design system, SEO files, strict security headers, real 404s.

Not built, on purpose (the spec says not to): the game engine, computer opponent, matchmaking and room server. The play pages
validate input and then say honestly that the feature isn't live. Feature flags in `lib.py` (`FEATURES`) control the "Coming soon"
badges and which features the homepage claims. Flip a flag only when the feature really works.

## Layout

- `lib.py` config, feature flags, icons, board illustration generator
- `pages.py` all page content
- `build.py` layout, metadata, sitemap, robots, headers
- `serve.py` local server with production-like 404 and room routing
- `static/` CSS, JS, logo, favicon (copied as is)

## Before going live

- `og-image.svg` should be exported to a 1200x630 PNG (most social networks ignore SVG previews) and referenced in `build.py`.
- Add PNG icons (180, 192, 512) for iOS and the web manifest.
- Replace the Privacy Policy and Terms drafts with reviewed text; add a real contact channel on `/contact/`.
- Review the "Quoridor" name (and any domain you pick) for trademark issues.
- Set `site_url` in `site.json` once the final address is known, then rebuild.
- When rooms exist, the host must serve `/room/<id>/` from `room/index.html` with a 200 (see `serve.py`; `_redirects` does this on Netlify / Cloudflare Pages).
