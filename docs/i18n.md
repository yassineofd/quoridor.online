# Languages

The site and the game are available in English, Spanish, French, German and Arabic (right to left). Visitors pick a language with the
globe button in the header. English is the source: every page is written in English in `pages.py`, and the other four languages are
translations of it.

## Language is never a barrier to playing

The language is a display choice of one browser. It is **never sent to the game server**, which has no idea which language anyone uses.

- One matchmaking queue and one set of rooms serve everybody. An Arabic page and a Spanish page are paired like any other two.
- The server speaks in codes, not sentences: a game snapshot carries moves and a `reason` code (`resign`, `disconnect`), and a refused
  request carries an error code (`not-your-turn`, `overlap`, ...). Each browser turns the code into words in its own language
  (`QuoridorI18n.errorText`). The server's English text is only a fallback for a code the page does not know.
- Display names may use letters and digits of any alphabet (`valid_username` in `server/rooms.py`, the same rule in `play.js` and
  `room.js`). Direction-changing and control characters are refused. In a sentence, a name is wrapped in Unicode isolates when it or the
  language runs right to left, so it cannot scramble the words around it.
- There is no chat, so nothing a player types has to be understood by the opponent except their name.

`tests/test_i18n.py` and the language tests in `tests/test_ui.py` pair an Arabic and a Spanish browser, and a German and a French one,
and play them against each other.

## How it works

| Piece | Job |
|---|---|
| `i18n.py` | Build-time. Finds every piece of visible text in the built pages and tags it with `data-i18n="<id>"` (the id is a hash of the English text); attributes (`aria-label`, `title`, `alt`, `placeholder`, the page title and meta description) get `data-i18n-attr="<attribute>:<id>"`. Also checks and lints translations. |
| `translations/<lang>.txt` | One line per text: `<id>|<translation>`. Messages built by scripts use `<key>|<translation>`. |
| `translations/js-en.json` | The English version of every message the scripts build (game screen, errors, search status ...). |
| `build.py` | Writes `assets/i18n/<lang>.json` (what the browser downloads) and `assets/js/i18n-en.js`. |
| `static/assets/js/head.js` | Before the first paint: picks the language (`?lang=xx`, the saved choice, the browser's language list, else English), sets `lang` and `dir`. |
| `static/assets/js/i18n.js` | Loads the catalog, swaps the text, runs the translate button, and offers `QuoridorI18n.t('key', {param})` to the other scripts. |

English needs no download: it is the page itself. Anything missing from a catalog stays English. The saved choice is the `quoridor.lang`
entry in the browser's local storage (the Privacy Policy says so).

Icons and form fields inside a text are written as `<svg/>`, `<input/>` or `<img/>` in the translation; the browser puts the original
element back there, so buttons keep their icons and checkboxes keep their state. Links are written root-relative (`/play/`) in
translations and made relative to the page by `i18n.js`.

## Changing or adding text

1. Change the English in `pages.py` (or `translations/js-en.json` for a message built by a script).
2. `python i18n.py status` shows what is untranslated; `python i18n.py missing es` prints it as `id|English` lines.
3. Add the lines to each `translations/<lang>.txt` with the translation after the `|`. Keep the markup, links and `{parameters}`
   exactly as in the English; `python i18n.py lint` catches mistakes.
4. `python build.py && python check.py`. `check.py` and `tests/test_i18n.py` fail while any language is incomplete or an entry is unused.

The id comes from the English text, so editing an English sentence makes its old translations "unused" and the new sentence "missing":
nothing silently shows a stale translation.

Text that must not be translated (the brand name, text a script fills in) carries `data-i18n-skip`.

### Adding a language

Add it to `LANGUAGES` in `i18n.py` (and to `LANGS` in `static/assets/js/head.js`, `NAMES`/`RTL` in `static/assets/js/i18n.js`), create
`translations/<code>.txt`, and fill it in as above. For a right-to-left language set the direction in those two JS files; the
stylesheet already uses logical properties (`inline-start`, `inline-end`) so it mirrors itself.

## Notes

- The legal pages say the English text applies if a translation differs. Have the translations of the Privacy Policy and Terms reviewed
  by a native speaker before relying on them.
- The contact form's email draft stays in English (subject and field names), so the person reading the mailbox can read it.
- Wording that needs a plural noun (`{n} seconds`) is avoided in messages; translations use "{n} s" instead, which works in every language.
